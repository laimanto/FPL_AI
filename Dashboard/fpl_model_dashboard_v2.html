FPL Points Prediction — Model Performance

v2

Trained on 8 seasons (2016-17 through 2024-25, 126,076 rows), validated on the entirely unseen 2025-26 season. Ridge regression is a reference baseline only. The LightGBM + Random Forest ensemble is the best-performing result overall. This page also covers the downstream squad optimizer that turns those predictions into an actual 15-man squad recommendation.

Live-deployment validation (walk-forward)

The card above holds out all of 2025-26 at once — one static split. A stronger, more realistic test: retrain the model fresh before every single gameweek using only data strictly before it, then predict that gameweek — exactly what a real live weekly deployment would have seen, rather than one holdout drawn all at once.

Run across all 38 gameweeks of 2025-26 (29,747 rows, ensemble model only). Result: statistically consistent with — and very slightly better than — the single-holdout number above, confirming the model generalizes the same way under this more realistic evaluation. Took ~2 hours of wall-clock (38 fresh retrains, mostly Random Forest fit time) run in checkpointed chunks due to this environment's ~20-25min background-task limit.

defensive_contribution_last5_per_game and dc_threshold_hit_rate_last5 show 0% weight — not because they're unhelpful, but because 2025-26 is held out as validation and is the only season where this stat exists at all, so the model never saw a real value for it during training. They're seeded for when a future season with real defensive-contribution history joins the training set. Confirmed against multiple sources that this rule applies to defenders and midfielders only — forwards and goalkeepers are not eligible, so the threshold is left as a true "not applicable" for those positions rather than an unreachable number.

Tested whether pooling every position into one model hurts goalkeeper-specific predictions (since features like saves_last5_per_game only mean something for GKP): a GK-only model trained just on goalkeepers scored almost identically to the pooled model evaluated on the same GK rows (RMSE 1.3700 vs 1.3720, R² 0.4763 vs 0.4747) — negligible difference. Position is itself a feature, so the tree can branch on it early and learn position-specific patterns without needing separate models.

Same-venue form: EMA replaced a flat 3-game average. ema_same_venue_ppg is an exponentially-weighted average (span=5) over the player's full home-only or away-only history, swapped in for a flat mean over just the last 3 same-venue games. Tested against the production baseline: a small, consistent RMSE/R² improvement on every model, and the feature itself ranks #14 by importance versus #30 for the version it replaced. Also tested keeping both versions side by side instead of swapping — no better (the two are 0.96 correlated, importance just fragments across them) — confirming the swap, not the union, was correct.

Is now_cost's dominance just the market echoing form, not new information? Tested by removing it from the feature set entirely: the accuracy drop is small but real and consistent across every model, with transfers_balance/transfers_in absorbing most of the importance it gives up. So cost is carrying a little genuine signal beyond what the rest of the feature set already encodes — kept in for now. Worth revisiting only if a future team-optimizer (picking players by predicted-points-per-cost within a budget) needs predictions that don't partly echo the price they're being divided by.

NEW Betting-market implied win/draw/loss probability adopted. market_implied_win_prob / _draw_prob / _loss_prob come from Bet365 pre-kickoff 1x2 odds (football-data.co.uk, free, all 10 seasons, 100% row coverage), converted to probability and stripped of the bookmaker's overround. This is the first feature in the model that isn't derived from historical results/prices/transfers — it reflects the market's own pre-match assessment, which can price in team-news/lineup information the rest of the pipeline has no historical access to. Consistent small win across every model when added, with Ridge gaining the most (it has no other way to construct a market-consensus signal from its linear inputs). All 3 features land in the top 20 by importance.

Explored further, not adopted: the same odds files also carry over/under total-goals odds and an Asian handicap line. Tested both as additional features (market_implied_over2_5_prob, a match-level "expected goal environment" signal; market_expected_goal_margin, a continuous alternative to win/draw/loss). Result: flat-to-slightly-negative net effect — the over/under signal has real standalone importance but is correlated enough with existing team-strength features that it doesn't add net accuracy, and the handicap margin is largely redundant with the win/draw/loss probabilities already adopted (same market view, two different encodings). Neither made the cut. Also looked into player-level "anytime goalscorer"/top-scorer odds — that's a different market entirely and isn't in this free data source at all; would need a different, likely-paid provider, not pursued.

Betting-market line movement: tested, measured a real win, excluded anyway. A feature tracking the change in this team's implied win probability between the opening and closing odds line (Bet365) scored a consistent improvement in backtesting — the single strongest new feature tried, #4 by importance, ahead of either win/draw/loss probability on its own. Excluded from production regardless: the FPL transfer deadline falls ~90 minutes before only the first match of a gameweek, while the other fixtures kick off across the following days — so a genuine closing line (the late team-news signal that made the backtest work) doesn't exist yet at deadline time for most of that week's matches. The backtest, built from a retrospective archive, implicitly assumed access to information a live system wouldn't actually have before predictions are needed — so the measured improvement likely wouldn't replicate live. Decision: leave it out rather than ship a feature whose live behavior doesn't match what was validated.

Random Forest hyperparameters retuned, LightGBM's left alone. A small sweep (8 LightGBM configs, 6 Random Forest configs, chosen on the internal 2024-25 tuning slice, confirmed once on the true holdout) found a real Random Forest improvement (n_estimators=800, max_depth=14, min_samples_leaf=20, max_features=0.4, was 400/10/15/0.6) but no genuine LightGBM improvement — the sweep's "best" LightGBM config scored better on the tuning slice yet slightly worse on the real holdout, a textbook case of tuning-slice noise rather than a real gain. Only the Random Forest change was kept.

Also tried this round, not adopted: team-level EMA for the venue-split team-form features (mirroring the player-level EMA win above, but for teams) — flat to slightly negative, team-level cumulative form apparently isn't as stale a signal as the player-level version was. Ensemble stacking (a learned linear blend of the base models instead of a flat 50/50 average) — negligible improvement, not worth the added complexity. Time-decay sample weighting (weighting recent seasons more heavily) — looked better on the internal tuning slice but that improvement evaporated on the true holdout, another tuning-slice-noise case.

Squad Optimizer

A separate layer downstream of the prediction model above — turns pred_ensemble into an actual 15-man squad recommendation, solved fresh every gameweek. Doesn't touch the model or its predictions at all.

An integer linear program (ILP, solved via PuLP + CBC) picks, from every available player that gameweek (the full ~500-900 candidate pool, no pre-filtering):

  • A 15-man squad: exactly 2 GKP, 5 DEF, 5 MID, 3 FWD, total cost ≤ £100m
  • A starting XI: 1 GKP, DEF 3-5, MID 3-5, FWD 1-3 — formation chosen freely each week, not fixed
  • A captain (predicted points doubled) and vice-captain (real FPL fallback if the captain doesn't play, simulated via an autosub + captain→VC engine matching real FPL rules)
  • Max 3 players from any one real-life club

Objective: maximize starting-XI predicted points, plus a small tiebreaker on bench players' predicted points, subject to one constraint — a player can only be benched (owned but not started) if they started (60+ minutes) their own team's most recent match. That single rule is the end result of testing several alternatives head-to-head on a full 38-gameweek backtest, not a first guess — see the comparison below.

Squad Optimizer: strategies compared

StrategyTotal actual pts (season)Avg bench costZero-output bench incidents

The starting point had a real bug: the original objective had no bench-cost term at all — only a shared £100m budget cap — so nothing rewarded a cheap, reliable bench. One player sat on the bench 32 of 38 gameweeks, started 0, scored 10 total points all season, and was never once actually used as a real substitute — cheap enough to be "free" under the old objective, but effectively guaranteed zero output.

Adding a bench-cost penalty fixed the budget-waste problem but made the reliability problem worse (32 → 32 zero-output incidents, no change) — a pure cost incentive rewards being cheap, not being reliable, so it made the trap more attractive, not less. Adding the appearance-floor rule directly fixed reliability (32 → 1 incident) but cost points versus having no cost mechanism at all when stacked on top of the penalty.

The question that settled it: does the cost penalty still earn its keep once the floor already fixes reliability directly? No — once a player can only be benched by having proven themselves reliable, the penalty's only remaining job is squeezing an already-cheap, already-reliable pool toward its literal cheapest member, trading away bench value that occasionally scores via genuine autosubs for budget that barely moves the needle on an already-affordable starting XI. The cost penalty was removed entirely — final strategy is the appearance floor alone, no cost term at all.

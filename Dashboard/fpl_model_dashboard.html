defensive_contribution_last5_per_game and dc_threshold_hit_rate_last5 show 0% weight — not because they're unhelpful, but because 2025-26 is held out as validation and is the only season where this stat exists at all, so the model never saw a real value for it during training. They're seeded for when a future season with real defensive-contribution history joins the training set. Confirmed against multiple sources that this rule applies to defenders and midfielders only — forwards and goalkeepers are not eligible, so the threshold is left as a true "not applicable" for those positions rather than an unreachable number.

Tested whether pooling every position into one model hurts goalkeeper-specific predictions (since features like saves_last5_per_game only mean something for GKP): a GK-only model trained just on goalkeepers scored almost identically to the pooled model evaluated on the same GK rows (RMSE 1.3700 vs 1.3720, R² 0.4763 vs 0.4747) — negligible difference. Position is itself a feature, so the tree can branch on it early and learn position-specific patterns without needing separate models.

Same-venue form: EMA replaced a flat 3-game average. ema_same_venue_ppg is an exponentially-weighted average (span=5) over the player's full home-only or away-only history, swapped in for a flat mean over just the last 3 same-venue games. Tested against the production baseline: a small, consistent RMSE/R² improvement on every model, and the feature itself ranks #11 by importance versus #30 for the version it replaced. Also tested keeping both versions side by side instead of swapping — no better (the two are 0.96 correlated, importance just fragments across them) — confirming the swap, not the union, was correct.

Is now_cost's dominance just the market echoing form, not new information? Tested by removing it from the feature set entirely: the accuracy drop is small but real and consistent across every model (ensemble R² 0.3559 → 0.3515, RMSE 1.8874 → 1.8938), with transfers_balance/transfers_in absorbing most of the importance it gives up. So cost is carrying a little genuine signal beyond what the rest of the feature set already encodes — kept in for now. Worth revisiting only if a future team-optimizer (picking players by predicted-points-per-cost within a budget) needs predictions that don't partly echo the price they're being divided by.
